certbot-go

一个支持多域名自动申请、续期 SSL 证书的工具。基于 lego 实现 ACME DNS-01 验证，单个二进制文件，可作为守护进程长期运行。

下载最新版本 查看源码

特性

面向需要同时维护多个域名证书的个人与小团队。

📜

多域名、通配符证书

一份配置文件管理多张证书，每张证书可包含多个域名，支持 *.example.com 通配符。

🔁

自动续期

守护进程按 check_interval 定期检查，在到期前 renew_before 时间内自动续签。

☁️

多 DNS 服务商

通过 dns_provider 选择阿里云云解析（alidns）或腾讯云 DNSPod（dnspod），自动增删 ACME challenge TXT 记录。

🔗

CNAME 委托验证

域名托管在不支持 API 的服务商（如天翼云）时，只需添加一条 CNAME，把验证委托给受支持的服务商。

⚙️

单次或守护进程

--once 单次执行即退出，适合 cron；默认模式常驻运行，可配合 systemd / supervisor。

🔐

凭证来自环境变量

配置文件支持 $ENV_VAR 引用，密钥可以放在 .env 或服务环境变量中，不落入配置文件。

两种验证模式

certbot-go 使用 DNS-01 验证，根据域名是否托管在所选 DNS 服务商上，选择直接模式或 CNAME 委托模式。

直接模式

域名本身就在阿里云云解析或腾讯云 DNSPod 上解析。不设置 challenge_delegate，程序直接通过 API 在域名下操作 _acme-challenge TXT 记录，无需任何手动步骤。

certificates:
  - name: example.com
    domains:
      - "example.com"
      - "*.example.com"
    # 不写 challenge_delegate 即为直接模式

CNAME 委托模式

域名托管在不支持 API 的服务商。在原 DNS 上一次性添加 CNAME，把 _acme-challenge 指向一个托管在所选服务商上的委托域名，程序随后只操作委托域名上的 TXT 记录。

  1. 在原 DNS 添加：
    _acme-challenge.example.com CNAME _acme-challenge.example.proxy-acme.com
  2. 配置中填写 challenge_delegate
certificates:
  - name: example.com
    domains:
      - "example.com"
      - "*.example.com"
    challenge_delegate: "example.proxy-acme.com"

快速开始

从下载到拿到第一张证书只需四步。

  1. 下载可执行文件

    前往 Release 页面 下载对应平台的版本，支持 Linux、macOS、Windows 的 amd64 与 arm64。

    # 以 Linux amd64 为例
chmod +x certbot-go-linux_amd64
sudo mv certbot-go-linux_amd64 /usr/local/bin/certbot-go
certbot-go --version
    macOS 用户注意：从浏览器下载的二进制文件会被 Gatekeeper 标记为隔离，首次运行时可能提示“无法打开，因为 Apple 无法检查其是否包含恶意软件”或“无法验证开发者”。任选一种方式解决：
    • 打开 系统设置 → 隐私与安全性，在“安全性”区域找到被阻止的 certbot-go，点击 仍要打开，然后再次运行。
    • 或者直接在终端移除隔离属性：
    xattr -d com.apple.quarantine /path/to/certbot-go

  2. 准备 DNS 服务商 API 凭证

    服务商dns_provider凭证最小权限
    阿里云云解析alidnsAccessKey ID / Secret（建议 RAM 子账号）AliyunDNSFullAccess
    腾讯云 DNSPoddnspodSecretId / SecretKey（建议 CAM 子用户）QcloudDNSPodFullAccess

  3. 编写配置文件

    按下面的示例修改成你的真实配置。完整示例见仓库中的 deploy/config.example.yaml。

    ⚠️ 首次调试建议使用 staging 目录 https://acme-staging-v02.api.letsencrypt.org/directory，避免触发 Let's Encrypt 的速率限制。验证通过后再切换到生产目录。
    # Let's Encrypt 账号邮箱，用于证书到期提醒
email: you@example.com

# ACME 目录地址
# 生产环境: https://acme-v02.api.letsencrypt.org/directory
# 测试环境: https://acme-staging-v02.api.letsencrypt.org/directory
acme_directory: https://acme-staging-v02.api.letsencrypt.org/directory

# 证书存储目录，每个证书一个子目录
# 子目录内包含: fullchain.pem, privkey.pem, chain.pem, metadata.json
cert_dir: /etc/letsencrypt/live

# ACME 账号信息存储目录
account_dir: /etc/letsencrypt/accounts

# 续签检查间隔（daemon 模式下有效）
check_interval: 12h

# 在证书到期前多久开始续签
renew_before: 720h  # 30 天

# DNS 服务商: alidns（默认）或 dnspod，只需填写所选服务商的凭证
dns_provider: alidns

alidns:
  access_key_id: "$ALICLOUD_ACCESS_KEY"
  access_key_secret: "$ALICLOUD_SECRET_KEY"

dnspod:
  secret_id: "$TENCENTCLOUD_SECRET_ID"
  secret_key: "$TENCENTCLOUD_SECRET_KEY"

certificates:
  # 直接模式：域名托管在所选 DNS 服务商上
  - name: example.com
    domains:
      - "example.com"
      - "*.example.com"

  # CNAME 委托模式：需先在原 DNS 添加
  #   _acme-challenge.example.org  CNAME  _acme-challenge.example-org.proxy-acme.com
  - name: example.org
    domains:
      - "example.org"
      - "*.example.org"
    challenge_delegate: "example-org.proxy-acme.com"

  4. 运行

    单次运行，申请或续期后立即退出：

    certbot-go --config config.yaml --once

    守护进程模式，常驻并定期检查续期：

    certbot-go --config config.yaml

    证书输出在 cert_dir/<name>/ 下，包含 fullchain.pem、privkey.pem、chain.pem 与 metadata.json，可直接给 Nginx、Caddy 等服务使用。

作为系统服务部署

守护进程模式推荐通过 systemd 或 supervisor 托管。两份模板都在仓库的 deploy/ 目录中，使用前请按实际路径修改；若凭证通过环境变量引用，还需在服务配置中注入这些变量。

systemd：/etc/systemd/system/certbot-go.service 
[Unit]
Description=certbot-go ACME certificate manager
Wants=network-online.target
After=network-online.target

[Service]
Type=simple
ExecStart=/usr/local/bin/certbot-go --config /etc/certbot-go/config.yaml
Restart=on-failure
RestartSec=10

# Security hardening
NoNewPrivileges=yes
PrivateTmp=yes
ProtectSystem=strict
ReadWritePaths=/etc/letsencrypt

# DNS provider credentials (recommended: environment file)
EnvironmentFile=-/etc/certbot-go/.env

[Install]
WantedBy=multi-user.target
# 注册并启动服务
sudo systemctl daemon-reload
sudo systemctl enable --now certbot-go
sudo journalctl -u certbot-go -f
supervisor：/etc/supervisor/conf.d/certbot-go.conf 
[program:certbot-go]
directory = /etc/certbot-go
command = /usr/local/bin/certbot-go --config /etc/certbot-go/config.yaml
stopasgroup = true
killasgroup = true
autostart = true
startsecs = 5
autorestart = true
startretries = 10
user = root
redirect_stderr = false

stdout_logfile = /var/log/certbot-go.log
stdout_logfile_maxbytes = 32MB
stdout_logfile_backups = 2

stderr_logfile = /var/log/certbot-go.err.log
stderr_logfile_maxbytes = 32MB
stderr_logfile_backups = 2

environment = ALICLOUD_ACCESS_KEY="",ALICLOUD_SECRET_KEY=""

从源码构建

需要 Go 1.27 或更高版本。

git clone https://github.com/AyakuraYuki/certbot-go.git
cd certbot-go
make init     # 从 deploy/ 复制 config.yaml 与 .env 模板
make build    # 产物位于 build/certbot-go
make run      # 等价于 --once 单次运行
make test
